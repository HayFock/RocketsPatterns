# Паттерны проектирования на семействе «Ракеты»

Учебный проект на C++. Семейство объектов: базовый класс `Rockets` и его наследники
`OrbitalRocket` (орбитальная), `InterPlanetaryRocket` (межпланетная) и `ReusableRocket` (многоразовая).

## Файлы проекта

| Файл | Что внутри |
|------|-----------|
| `main.cpp` | Семейство ракет, фабричные методы, стратегии запуска, декораторы итераторов, демонстрация работы |
| `PatternTemplates.h` | Шаблонные контейнеры (`StackClass`, `ArrayClass`) с общим базовым классом `ContainerBase`, паттерн «Итератор», декоратор итератора, адаптер STL-итератора |
| `screenshots/` | Скриншоты работающей программы |

## Ранее реализованные паттерны

- **Фабричный метод:** `CreateRocket()` создаёт ракету нужного типа.
- **Итератор:** `StackIterator`, `ArrayIterator`; контейнеры создают итераторы функцией `GetIterator()`.
- **Декоратор:** `RocketFuelDecorator`, `RocketMassDecorator`, `RocketEfficiencyDecorator` фильтруют ракеты при обходе.
- **Адаптер:** `ConstIteratorAdapter` позволяет обходить `std::list` так же, как наши контейнеры.

# Стратегия

## Задача

Реализовать возможность запускать ракеты различными способами: вертикально с наземной площадки
(`Vertical`), с самолёта-носителя (`AirDrop`) или с морской платформы (`SeaPlatform`). Способ запуска
нужно уметь менять во время работы программы, а перечень способов может расширяться.
**Изменять интерфейс существующих функций класса нельзя** (остальной код программы
вызывает `Launch()` и `DisplayInfo()`).

## Решение «в лоб» (без использования паттернов)

1. Объявить перечисляемый тип способа запуска.
2. Добавить в класс `Rockets` свойство «способ запуска».
3. Переписать функцию `Launch()` в каждом классе-наследнике так, чтобы она через `if` или `switch`
   выбирала, что делать, в зависимости от способа запуска.

Недостатки: одинаковые ветвления дублируются в трёх классах, а каждый новый способ запуска
требует правок во всех классах семейства.

## Решение с использованием паттерна «Стратегия»

1. Объявлен перечисляемый тип способа запуска `LaunchMannerEnum`.
2. Создан абстрактный класс стратегии `LaunchStrategy` с функцией `Launch()`.
3. От него унаследованы конкретные стратегии: `VerticalLaunchStrategy`, `AirDropLaunchStrategy`,
   `SeaPlatformLaunchStrategy`.
4. Разработан фабричный метод `CreateLaunchStrategy()` для создания стратегий.
5. Стратегия инкапсулирована в базовом классе `Rockets` в виде указателя `LaunchManner`;
   ракета владеет стратегией и удаляет её в деструкторе.
6. Интерфейс `Rockets` дополнен функциями `SetLaunchManner(LaunchStrategy*)` и
   `SetLaunchManner(LaunchMannerEnum)`. Старая стратегия при замене удаляется.
7. Каждый класс-наследник задаёт способ запуска по умолчанию в конструкторе.

Чтобы добавить новый способ запуска, достаточно создать новый класс стратегии, добавить значение
в `enum` и одну строку в фабричный метод. Классы ракет не изменяются.

## Краткая характеристика паттерна «Стратегия»

Паттерн «Стратегия» определяет семейство алгоритмов, инкапсулирует каждый из них и обеспечивает
их взаимозаменяемость. Он позволяет модифицировать алгоритмы независимо от их использования
на стороне клиента.

# Шаблонный метод

## Задача

1. Унифицировать структуру алгоритмов методов `Launch()` и `DisplayInfo()` родительского класса
   `Rockets` и унаследованных от него классов.
2. Уменьшить количество дублируемого кода: например, четыре одинаковые строки вывода
   (масса, грузоподъёмность, топливо, дальность) раньше повторялись в `DisplayInfo()`
   каждого из трёх наследников.

## Решение с использованием паттерна «Шаблонный метод»

1. Общая структура алгоритмов зафиксирована на уровне родительского класса.
   Функции `Launch()` и `DisplayInfo()` **перестали быть виртуальными**.
   - `Launch()`: название ракеты → проверка готовности → план полёта → запуск стратегией → хук `AfterLaunch()`.
   - `DisplayInfo()`: заголовок → общие данные → данные, специфичные для типа → эффективность.
2. Весь повторяющийся код (проверка готовности, вывод общих характеристик, вызов стратегии)
   реализован в родительском классе.
3. Весь специфический код перенесён в реализации шагов-методов в наследниках:
   `PrintType()`, `PrepareFlightPlan()`, `PrintSpecificInfo()`. Эти шаги объявлены
   чисто виртуальными в защищённой части класса.
4. Для необязательного шага использован «хук» `AfterLaunch()` (по умолчанию пустой).
   `ReusableRocket` переопределяет его и увеличивает счётчик полётов после каждого запуска.

## Краткая характеристика паттерна «Шаблонный метод»

Паттерн «Шаблонный метод» задаёт «скелет» алгоритма в методе, оставляя определение реализации
некоторых шагов унаследованным классам. Эти классы могут переопределять некоторые части алгоритма
без изменения его структуры.
